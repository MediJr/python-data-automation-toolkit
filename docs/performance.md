# Performance

One reproducible benchmark, measured on one computer. The numbers describe this workload
on this machine only; they are not a guarantee and were not extrapolated to other sizes.

## Workload

Generated by [benchmarks/generate_data.py](../benchmarks/generate_data.py) (fixed seed, so
the same bytes every time): 12 CSV branch files × 10,000 orders = **120,000 rows, 5.2 MB**,
plus a targets file. The workflow [benchmarks/benchmark.yaml](../benchmarks/benchmark.yaml)
types the `amount` (decimal) and `order_date` (date) columns, then:

| Step | Rows out |
| --- | --- |
| concatenate 12 files | 120,000 |
| filter `status = closed` and `amount > 0` | 90,048 |
| aggregate per region (sum, count, mean rounded) | 8 |
| join with targets (`one_to_one`, `require_match`) | 8 |
| sort the closed orders by `order_id` | 90,048 |

and writes three verified outputs: `kpis.csv`, `kpis.xlsx` (8 rows) and
`closed_orders.csv` (90,048 rows).

## Method

[benchmarks/run_benchmark.py](../benchmarks/run_benchmark.py) runs the real command
(`python -m data_automation run benchmarks/benchmark.yaml`) once to warm up, then 3 times,
each time from empty `output/` and `runs/` folders. [benchmarks/measure.py](../benchmarks/measure.py)
starts the process in a Windows Job Object: wall time is measured from process creation to
exit (Python start-up and imports included), memory is the kernel's peak committed private
memory of the process (no sampling). Calibration: a process allocating 200 MiB measures
207 MiB. [benchmarks/verify_outputs.py](../benchmarks/verify_outputs.py) then recomputes
both CSV outputs with the standard library only (it does not import the package) and
compares them line by line.

## Results

Windows 11 (10.0.26300), AMD64 processor with 12 logical CPUs, Python 3.14.7, pandas 3.0.6,
`data_automation` 0.1.0 — the full output is in [benchmarks/results.json](../benchmarks/results.json).

| Measure | Value |
| --- | --- |
| Wall time, 3 runs | 6.54 s, 7.15 s, 7.49 s (median 7.15 s) |
| Peak committed memory | 566–567 MiB |
| Independent verification | both CSV outputs identical (8 and 90,048 rows) |

Where the time goes (from the run report of the last run, total 5.0 s inside the run; the
rest is Python start-up and about 1 s of imports, mostly pandas):

| Phase | Seconds |
| --- | --- |
| Read and type 12 files | 1.11 |
| Steps (concatenate 0.48, filter 0.24, aggregate 0.28, join 0.01, sort 0.12) | 1.12 |
| Write + read back + compare `closed_orders.csv` (90,048 rows) | 2.70 |
| `kpis.csv` and `kpis.xlsx` | 0.02 |

## Interpretation

- Verification is the largest cost: every output is read back and compared value by value
  before publication. This is deliberate (ADR-0007) and is not optional.
- Memory is about **110 times the input size** here: values are parsed into Python objects
  (exact `Decimal`s, dates) and several copies exist while steps run. Data is processed
  entirely in memory, so very large inputs (millions of rows) are outside the intended use;
  no measurement was made at that scale.
- XLSX reading was not benchmarked here (the workload reads CSV only). Service 1 measured
  XLSX reading about 4 times slower than CSV with openpyxl; the examples therefore use CSV
  for bulk data.

## Reproduce

```powershell
.venv\Scripts\python.exe benchmarks\run_benchmark.py
```

The generated data and outputs go to `benchmarks/work/` (ignored by git). The script exits
with a non-zero code if a run fails or the independent verification finds a difference.
Timings vary between runs and machines; memory is more stable.
